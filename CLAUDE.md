# CLAUDE.md

Guidance for Claude Code in this repo.

## What this is

A local-first project and task management web app — a simple, reliable core
(projects, tasks, Focus, search, trash, dashboard) with a local agent
(llama.cpp + tools + MCP + retrieval) built on top. `README.md` has the
architecture; `TODO.md` is the backlog; `DONE.md` is the completion log.

## Commands

```bash
./main.sh                 # bootstrap env/deps, migrate, start backend + frontend
./test.sh                 # backend pytest/ruff/mypy + frontend Vitest/lint/build
./scripts/backup_db.sh    # online snapshot of data/app.db → data/backups/
```

- After bumping a backend dep: `cd backend && .venv/bin/python -m pip freeze
  --exclude-editable > requirements.lock`.
- The deployed instance runs via `docker compose`; `./main.sh` is dev-only —
  never both against the same `data/`.
- Frontend changes whose surface is the rendered page (especially
  pointer-drag) verify with the `verifier-browser` skill, not just tests.

## Rules

- **The service layer is the only write path.** UI routes, API clients, and
  agent tools are peers: every mutation goes through `services/`, gets
  validated, respects soft deletes, and lands in `activity_events`.
- **The agent inherits that**: tools only, every action auditable and undoable
  via trash, no hard deletes ever, model output Pydantic-validated at the
  boundary.
- **Local-first is load-bearing**: llama.cpp on this machine, retrieval
  in-process (FTS5 first). No cloud model providers, no external vector DB.
- **The "Do not build yet" list in README.md is binding** (no multi-user
  auth, Celery, external vector DB, cloud providers).
- **Git:** never commit to `main`. Branch → PR → squash-merge on green CI
  (`gh pr checks --watch`, then `gh pr merge --squash`). Run `./test.sh`
  before pushing.
- **Eval gate:** prompt/model/loop changes run the opt-in harness
  (`PCC_AGENT_EVALS=1 pytest tests/test_agent_evals.py -v -s`) and must not
  regress the baseline in `docs/agent-design.md`.
- **Ask before adding a dependency.**
- Work from `TODO.md`; flag scope expansion rather than silently doing it.
  Push back when something seems wrong.

## Code rules

- Python 3.11+, SQLAlchemy 2.0 typed syntax, Pydantic v2, type hints on every
  signature.
- Alembic for every schema change — review the autogenerated file.
- Soft deletes only (`deleted_at`, filtered via the service helper);
  `activity_events` is the append-only exception.
- Structured logging with `structlog`, request ID bound on every request.
- Frontend: React + Vite + TS strict; API calls through `src/api/`; feature
  folders; no state library; no `any` without a reason.

## UI conventions

- No element inherits the 16px root size.
- Metadata words are colored words, never pills.
- Creating is lane-scoped — no global create buttons.
- A row under a status group header carries an exceptions-only meta line,
  never the word the header already says (the done archive's chip is the
  deliberate exception).

## Definition of done

The vertical path works end-to-end; at least one happy-path backend test;
migrations committed with schema changes; a removal takes its docs, routes,
services, env vars, and tables with it in the same PR; README updated when
setup, commands, schema, or status changed.
